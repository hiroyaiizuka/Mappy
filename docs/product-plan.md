# Mappy 製品計画

更新日: 2026-09-26

本書は製品方針と受入条件を記す。現在は GitHub Release ＋ BRAT のベータ（0.x）として公開しながら、専用テスト Vault で検証を進めており、機能の実装と全受入条件の達成を分けて扱う。最新のユーザー選択により、通常の入力は「H2 のルート＋インデントした箇条書き」とし、本文・リンク・画像を持たせる。従来の見出し階層も保持し、明示操作で変換する。通常の Markdown が正本であることは変えない。

H0a の静的検査・テスト・配布物検証に加え、M1〜M4 の機能を試作し、DOM テスト、Obsidian に依存しないブラウザ検証ページ（`npm run harness:browser`）、Obsidian の専用環境（`scripts/e2e/` のケースを `npm run harness:e2e` で CDP 経由で実行）で検証を進めている。性能はブラウザ検証ページで計測済み（§6）だが実機でのレイアウト別の計測、モバイルやネイティブ IME の確認は完了していない。最新の実行結果は `artifacts/` の記録を参照する。残項目の起票と進め方は [linear-workflow.md](./linear-workflow.md) に記す。

## 1. 目指す体験

Obsidian のノートを、文章を書く画面と構造を考える画面の両方から扱えるようにする。XMind に近い素早いノード操作、Light Mindmap に近い手軽な移動・拡大縮小、MarkMind のようなリンク・画像の扱いやすさを、通常の Markdown ファイル上で実現する。

- 同じノートを Markdown／マインドマップで切り替えられる。
- 左にマップ、右に Obsidian 標準の Markdown エディタを並べ、編集結果を随時反映できる。
- ノードに内部リンク、外部リンク、画像を表示し、その場で利用できる。
- キーボードで兄弟・子ノードを追加し、編集・移動・折りたたみを行える。
- 拡大縮小中や本文更新後も、見ていた位置と選択をできるだけ維持する。
- 添付画像のように横軸へ章を並べ、下位項目を上下へ交互に伸ばすタイムラインを利用する。
- ドラッグだけでノードの並べ替えと親変更ができ、移動先が事前に分かる（XMind に近い操作感）。
- 空白をダブルクリックして 2 つ目以降のマインドマップ（フリートピック）を作り、あとで本体の枝にできる（XMind のフリートピックに相当）。
- 通常マップ・タイムラインに加えて、階層図（ルートを上に置く段揃えの木）の表示を選び、イシューツリーやロジックツリーを描ける。
- 別のノートに `![[マップノート]]` と書くと、そのノートの閲覧・ライブプレビュー・ホバープレビューの中に読み取り専用のマップが現れる。`#見出し` で枝だけを出せる。
- マップを開いたまま過去のマップを検索し、現在のマップに呼び出して並べて見る。
- ルートを中央に置き第一階層を左右へ振り分ける左右バランス配置を、4 つ目の形として選べる。
- マップを PNG／SVG に書き出して Obsidian の外へ持ち出す。
- 設定でテーマ（Obsidian に従う／明色／暗色）、新規マップの既定レイアウト、作成先フォルダを選ぶ。

今回の優先事項は、機能数よりも Markdown を壊さないことと操作の応答性である。関連線、境界線、PDF 注釈、付箋メモ、共同編集、Obsidian Canvas 連携は含めない（§7）。フリートピック（M7）、階層図（M8）、AI 機能（M9、有料オプション）、埋め込み表示（M10）、左右バランス配置（M11）、検索と呼び出し（M12）、書き出し（M13）、設定タブ（M14）は後続段階として本書に置き、M1〜M4 の受入条件を優先する。着手の順番は §5 末尾に記す。

## 3. 保存と表示の基本方針

### Markdown を正本にする

保存する内容は Vault 内の通常の `.md` と添付ファイルである。マップ用 JSON を別の正本として持たない。表示設定には必要に応じて frontmatter を使い、選択や一時的なズーム位置などの表示状態は内容と分ける。

現在の保存仕様は以下とする。

- H2 をルート、その下を順序なしリストのインデントで表す。文書直下の見出しが H2 だけ、または見出しがない場合はこの形式を使う。
- H2 以外の見出しがある既存文書は従来の見出し階層を維持する。本文の箇条書きを自動的にノードへ変えない。
- 箇条書きの最初の行、または見出しの文そのものをノードに表示し、別のタイトル欄を要求しない。空のノードを追加し、その場でテキストを入力する。
- 本文は原文範囲を保持する。リストの直接本文は最初の子より前の継続行を扱い、子リスト後の親の文章は保存したまま子の移動範囲へ含めない。
- ノードの移動では、そのノードに属する本文と子孫も一緒に扱う。
- 複数の最上位区画がある文書は、最初の見出し区画を本体、それより後ろの最上位区画をフリートピックとして自由配置する（§5 M7）。見出しのない文書、および最初の H2 より前に文書直下の箇条書きがある文書は、ファイル名を使った表示専用の仮想ルートを本体にする。どちらの場合も表示のためだけに見出しを書き足さない。
- コードブロック内の `#` は見出しとして扱わない。
- 見出しのない文章も保持し、勝手に削除・見出し化しない。
- 閲覧やレイアウト変更だけで、本文全体を整形し直さない。

リストの深さには6階層の制限を設けず、CommonMark の構文に従ってインデントを解釈する。従来の見出しモードだけは H6 が上限で、それを超える子追加・移動を拒否する。番号付き・タスクリストと配下の枝はノード化せず原文を保持する。

旧見出し形式からの変換は右クリック「リスト形式に変更」またはコマンド「現在のマップをリスト形式に変更」で実行し、マップの Undo で復元できるようにする。閲覧では書き換えない。本文の箇条書きが新しいノードになるなど、タイトル・件数・親子関係が変わる変換は拒否する。

### 文章とマップの同期

Markdown 側の見出し・箇条書きの追加・削除・階層変更・順序変更・本文変更をマップへ反映する。箇条書きの階層はインデント変更で更新できる。マップからの操作は、対象範囲への変更として Markdown に反映する。

同期の成立条件は「片側の変更が表示される」だけではない。未保存の編集、同じファイルを開いた複数ビュー、外部変更、Undo／Redo、日本語 IME を含めて内容が失われないことを条件にする。更新が競合した場合は、古い状態による上書きを防ぎ、再読込や操作のやり直しを案内する。

### ノードの内容

- 内部リンクは `[[ノート]]`、別名付きリンク、見出し・ブロックへのリンクを対象にする。
- 外部リンクと通常の Markdown リンクをクリックできるようにする。
- 画像は `![[画像.png]]` と `![説明](画像.png)` を基本にする。
- 画像を追加するときは Obsidian の添付ファイル設定に沿って保存する。
- リンクを開く操作、ノード選択、ドラッグ、テキスト編集を混同しない。
- 本文が長い場合はノード内で全量を広げず、本文表示・編集へ移れるようにする。

API、更新処理、責務の分割は [architecture.md](./architecture.md) で扱う。

## 4. 基本操作の推奨案

| 操作 | 初期割り当て |
| --- | --- |
| ノード選択 | クリック、矢印キー |
| 兄弟追加 | ノード選択中に Enter |
| 子追加 | ノード選択中に Tab |
| テキスト編集 | F2、ダブルクリックでインライン編集 |
| 編集確定／取消 | Enter／Escape。Tab は確定して子を追加 |
| リンク候補 | `[[` / `![[` でノート・パス・別名・添付の候補。候補表示中は Enter／Tab を候補選択に使う |
| 削除 | Delete／Backspace。本文と子孫を含む変更を Undo 可能にする。削除後の選択は 1 つ上の兄弟 → 1 つ下の兄弟 → 親（原文順、4 レイアウト共通。フリートピックのルートはトピック同士が兄弟で、残りがなければ本体のルート。仮想ルートは選ばず、同じ種類が残らなければ最上位で最も近いノード。LEV-204）。複数選択はないので単一ノードの規則だけ。実機 E41（2026-09-26、4 レイアウト × Delete／Backspace × 19 の形、Undo・画面外を含む）で確認済み |
| 折りたたみ | Space またはノードの開閉ボタン |
| 並べ替え・親変更・切り離し | ドラッグ。移動先を事前表示する。ノードのない空白で離すと、その枝が新しいフリートピックになる |
| トピックを追加 | 空白のダブルクリック、または空白の右クリック「トピックを追加」。押した位置に空の最上位区画を置き、その場で入力する |
| フリートピックの移動・合流 | トピックのルートをドラッグ。木ごと動き、空白で離すと frontmatter `mappy-topics` だけが変わる。ノードの上で離すとその子の枝になる（移動先を事前表示）。Escape で元の位置に戻す |
| 本体の移動 | 本体のルートをドラッグ。トピックは画面上の位置を保ち、`mappy-topics` の全項目が本体基準で書き換わる |
| 移動 | 背景ドラッグ、トラックパッドのスクロール |
| 拡大縮小 | ピンチ、Ctrl/Cmd＋スクロール、＋／−ボタン |
| 全体表示 | Fit ボタン |
| Markdown／マップ切り替え | ツールバーとコマンドパレット |

キー入力はマップにフォーカスがあるときだけ受け付ける。本文編集や日本語変換中の Enter／Tab を構造操作に使わない。通常のスクロールを拡大縮小へ強制的に置き換えず、カーソル中心のズームと表示領域の移動を別々に検証する。既存の Obsidian ショートカットと共存させる。

上部の子追加・兄弟追加などの操作行は設けず、キーボードと右クリックメニューから操作する。キャンバスを全面に広げ、レイアウト切り替えを左下、操作のポップオーバー（歯車 1 つ。Markdown に切り替え・マップを検索して呼び出す・書き出す の 3 項目）を右上、ズームを右下に浮かせて配置する。通常マップは直角線を使い、ルート周囲を広めに空ける。展開中の折りたたみ操作は枝の分岐点にカーソルを合わせると丸い − を表示する。補完はノード用 textarea の独自 UI であり、標準 Markdown エディタの補完をそのまま埋め込んだものではない。

## 5. 段階的ロードマップと受入条件

### H0a: 開発基盤

製品機能より先に、静的検査・単体テスト・配布物の確認を繰り返せる土台を作る。H0a の完了は、マップ操作の検証環境まで完成したことを意味しない。

- TypeScript の strict 型チェック、ビルド、ESLint と Obsidian 向けルール、EditorConfig による書式設定を整える。
- Vitest と CI を用意し、後続の Markdown 解析・変更・レイアウトを単体で検証できるようにする。
- manifest などのメタデータと配布物を検査する validator を用意する。
- 専用 test-vault の生成と、配置前の preflight を用意する。
- 10／100／500／2,000 ノードの fixture と、必要な受入条件・実機確認の計画を用意する。
- 公開前チェック、保存・同期の設計、まだ判断していない項目を文書化する。

**受入条件:** 一つの品質確認コマンドで静的検査・既存テスト・ビルド・配布物検査を実行でき、CI でも同じ判定になる。fixture と確認計画が共有され、失敗時にどの条件が壊れたか分かる。マップ UI やブラウザ操作テストの完成は、この段階の合格条件に含めない。公式 lint を通すだけでコミュニティ審査通過を保証する、という扱いにはしない。

### H0b: M1 とともに追加する DOM／ブラウザのハーネス

検証は3層に分ける。① Vitest（Node 環境、`obsidian` はモック）による純粋ロジックと DOM のテスト、② Obsidian に依存しないブラウザ検証ページ、③ 専用 Vault を開いた Obsidian 実機での確認（`docs/harness.md` の E01〜E38。CDP で操作し、再実行できるケースは `scripts/e2e/` に置いて `npm run harness:e2e` で走らせる）。③が E2E に相当し、②は E2E の代替ではない。

②の目的は、①で測れない実測サイズ・フォント・画像遅延・ポインター操作・ズームの見た目と、③では回しにくい性能計測を、Obsidian を起動せずに繰り返すことにある。

- 製品と同じ core / layout / interaction を読み込み、fixture を切り替えられるページを作る。Obsidian の API はモックし、保存・リンク解決・テーマ・IME はこのページで検証しない。
- 選択、パン、ズーム、開閉、ペインのサイズ変更などをブラウザで再現する。
- 日本語・同名見出し・リンク・画像・コードブロック・不均等な枝のケースを拡充する。
- 10／100／500／2,000 ノードの fixture（見出し形式、均等な枝、深い一列の枝、多数の兄弟、長い日本語、リンク・画像の 6 つの形）で、解析・配置・描画・入力反映の時間を 3 レイアウトで記録し（`scripts/browser-harness-perf.mjs`）、§6 の仮目標を実測値と判断に置き換える。基準端末・ブラウザ・条件を `artifacts/` に残す。
- ブラウザで代用できない Obsidian の Editor／Vault／リンク解決や IME の動作は、③の手順で確認する。

**受入条件:** ②で M1 の主要操作を再現でき、表示崩れと応答性を確認できる。①②③それぞれの範囲が明確で、②の成功を③の成功と呼ばない。10／100／500／2,000 ノードの描画・入力反映時間が条件付きで記録されている。現在は①②③が揃い、②は fixture 切替と選択・パン・ズーム・開閉・ペインのサイズ変更を headless Chrome で再現して `artifacts/browser-harness/` に記録し、性能計測は 24 文書 × 3 レイアウトの p50／p95 を基準端末・条件とともに `artifacts/performance/` に記録している（2026-09-18。§6 参照）。②の値は実機（LEV-33）と 500 ノードまで一致し、2,000 ノードでは実機の下限として読む。LEV-45（深い一列の 2,000 ノード）の修正後の再計測は深い一列の 500／2,000 ノード × 3 レイアウトで済み（`artifacts/lev-45-place-reflow-2026-09-18.md`）、実機（E10）でのレイアウト別・形別の計測と全形の再計測が残るため、H0b 全体の完了はまだ宣言しない。

### M1: 閲覧 MVP

- H2＋箇条書き、または既存の見出しと本文からツリーを作り、右向きのマップを表示する。
- 閲覧用の Markdown／マップ切り替えと、標準エディタとの左右分割を用意する。編集操作をまたぐ履歴の保証は M2 で検証する。右上の 2 ボタンだった切り替えと分割は、M3 の操作メニュー（歯車 1 つ）の先頭 2 項目に移し（2026-09-20、LEV-77）、同日 LEV-81 でメニューを 3 項目のポップオーバーに置き換えた際に切り替えだけを残した（分割はコマンドから）。コマンド「マップと Markdown を切り替え」「マインドマップと Markdown を並べる」はそのまま。
- Markdown の編集をマップへ反映する。

### M4: 横軸タイムライン

添付画像を基準に、ルートを左端へ置き、第一階層を横軸上に順番に配置する。下位の枝は上・下へ交互に配置し、本文・リンク・画像も通常マップと同じデータで表示する。日付や期間の入力は必須にしない。

- 横軸の項目順は Markdown の順序と一致させる。
- 枝の大きさを考慮して間隔を取り、隣接する枝の重なりを防ぐ。
- マップ／タイムラインの切り替えで内容を書き換えない。
- 通常マップと同じ選択、編集、開閉、ズームを利用する。
- ルートは濃い面、第一階層は枠付き、下位項目はテキストだけとする。線はテキストの手前で止め、閉じた枝には非表示の子孫数を表示する。

**受入条件:** 添付画像のような長い講座構成を、横軸と上下交互の枝で表現できる。長文・画像・深い枝が混在してもノードが重ならない。並べ替えが Markdown と両方に反映される。折りたたみと再展開の前後で内容が欠落しない。日付比例の目盛りやガントチャートは、この段階の要件に含めない。

### M7: フリートピック

ノードの木とは別に、マップ上の任意の位置へ XMind のフリートピックに相当する最上位トピックを置く。Markdown 側では 2 つ目以降の最上位区画（リスト形式では H2 とその配下のリスト、従来の見出し形式では最上位見出しの区画）そのものであり、新しい記法を持たない。位置だけを表示状態として frontmatter `mappy-topics` に持ち、内容と表示状態を分ける（§3）。付箋メモは採用しない（§7）。

- 表示: 文書の最初の見出し区画を本体のルートにし、それより後ろの最上位区画をフリートピックとして配置する。位置は `mappy-topics` に見出しの文をキーとしてレイアウト別に持ち、未設定なら本体の近くに重ならない既定位置へ置く。同じ見出しのトピックが複数あるときは、2 つ目以降のキーを `<見出し> (2)`、`<見出し> (3)`… とし（その文字列が別の見出しと重なるときは使われていない最小の番号）、原文順の n 番目が n 番目のキーを使う。既存の「ファイル名の仮想ルートで束ねる」表示は、見出しのない文書だけに残す。
- 追加: 空白のダブルクリック、または右クリック「トピックを追加」で文書末尾に新しい最上位区画（リスト形式では `## `）を追加し、その場でインライン入力する。押した位置を保存する。何も選択せずに「マップを検索して呼び出す」（M12）と、`![[別マップ]]` を見出しにした区画が同じ場所に足される（位置は未設定の既定配置。そのトピックは呼び出し先の木を枝として描く）。
- 編集: 通常のノードと同じ操作（インライン編集、子追加、本文、リンク・画像、折りたたみ）。マップ側の改名は `mappy-topics` のキーも同じ差分で更新する。Markdown 側の改名で位置が失われた場合は既定位置に戻る。
- 移動: ドラッグで位置を変える（frontmatter だけが変わる）。ノードの上へドロップするとその子になり（区画→リストの枝への変換）、本体の枝を空白へドロップすると新しいフリートピックになる（枝→区画への変換）。変換は本文・画像・インデントを保ち、タイトル・件数・親子関係が変わる変換は拒否する。ノードの隣へ運んだときの事前表示（仮ノードと青線）の間、合流先の親は運んだルートから動かない。合流先が位置未設定のトピックでも同じで、位置未設定のトピックの列は事前表示の間は積み直さず、離した（またはスロットが消えた）時点で積み直す。本体の枝を運ぶ事前表示でも同じ規則（2026-09-21 決定、LEV-95。M11）。さらに 4 レイアウトとも、子を持つ位置未設定トピックの子列（階層図・タイムラインでは子の行）へ別のトピックを運ぶ間も、仮ノードが出る前から位置未設定の木を直前の仮ノードなし配置に留める。親が運んでいる木を避けて先に逃げることがなく、子列の `snapTarget` を得て、preview 前後に親ルートを動かさずに期待する子順へ合流できる（2026-09-21。通常マップ・左右バランスは LEV-117、階層図・タイムラインは LEV-125）。引き換えに、ドラッグ中は他の位置未設定のトピックが運んでいる木を避けて動かず、避ける積み直しは離した時点で一度だけ起こる（位置未設定の列に積まれた次のトピックと運んでいる木が重なって見えることがある）。
- 削除・Undo: 区画ごと削除し、マップの履歴で戻せる。
- 通常マップ・タイムライン・階層図で同じトピックを表示し、位置はレイアウトごとに保持する。Excalidraw 挿入（M6）にはフリートピックを含めない（本体の木だけを 1 グループで挿入する。2026-09-21 決定、LEV-41。§7）。

**受入条件:** フリートピックの追加・編集・移動・合流・切り離し・削除を元へ戻せる。トピックを扱っても本体のノード・本文・他の frontmatter が変わらない。Markdown 側で 2 つ目の最上位区画を書くとマップにフリートピックとして現れ、マップ側の編集が Markdown に反映される。フリートピックを持つ文書を Mappy 以外で開くと、通常の見出しと箇条書きとして読める。複数の H2 を持つ既存文書は内容を変えずに本体＋フリートピックの表示へ移る。同じ見出しのトピックを個別に動かせる。片方を動かしてももう片方は動かず、選択と id は保持される。改名・削除・本体の移動・合流・切り離しでもキーが対応し続ける。位置未設定で子を持つトピックの子列へのドラッグでは、通常マップと左右バランスの両方で親ルートがドラッグ開始から preview まで動かず、離すと期待する子順へ合流し、Undo／Redo で元の原文と合流後の原文をバイト単位で往復する。

### M8: 階層図表示

通常マップとタイムラインに続く第三のレイアウト「階層図」。ルートを上に置き、同じ親の子を同じ段に揃えて下へ広げる（イシューツリー・ロジックツリー・組織図・WBS を描くための形）。名前は用途ではなく形で付ける。データと操作は通常マップと共通で、`mappy-layout: hierarchy` を任意の初期表示設定にする。

- 階層ごとに段を揃え、兄弟の順序は Markdown の順序と一致させる。「段を揃える」は XMind の組織図と同じ次の規則とする（2026-09-18 の本人フィードバックで精密化）:
  - 同じ親の子（兄弟）は同じ段（同じ上辺）に置く。
  - 異なる親の子（従兄弟）は、それぞれの親の下辺＋段間の隙間に置く。親に画像や本文があって背が高い場合はその親の子だけが下がり、他の枝の縦線は伸びない。
  - 親子をつなぐ縦線の長さは親の下辺から子の上辺までの隙間で一定（親ごとにバスの高さが決まり、幹と枝はその半分ずつ）。
  - 段間の隙間はノードの標準的な高さ程度: ルート直下 48px（枠付きの第一階層の高さ相当）、それ以下 32px（文字だけのノードの高さ相当。開閉ボタンの当たり判定 28px が収まる）。
- 枝の幅を考慮して間隔を取り、長い日本語や多数の兄弟で重ならない。背の高いノードが次の段の従兄弟と横に重ならないよう、占有幅は枝の幅で確保する。
- 選択、編集、並べ替え、折りたたみ、ズームを通常マップと同じにする。
- レイアウトボタンと frontmatter の扱いは M6 のタイムラインと同じ規則にする。Excalidraw 挿入は現在のレイアウトを反映する。

**受入条件:** 切り替えで内容を書き換えない。折りたたみと再展開の前後で内容が欠落しない。並べ替えが Markdown と両方に反映される。2,000 ノードで操作可能である。

### M10: 埋め込み表示

別のノートに書いた `![[マップノート]]` を、閲覧モード・ライブプレビュー・ホバープレビュー（ページプレビュー）の中で読み取り専用のマップとして描画する。Obsidian 標準の埋め込み記法だけを使い、Mappy 専用の記法を足さない。

- 対象は frontmatter に `mappy: true` を持つノートの埋め込みだけ。レイアウトは元ノートの `mappy-layout`（省略時は通常マップ）に従い、埋め込み側では指定しない。
- `![[ノート#見出し]]` はその区画をルートにした部分木を描く。同名見出しは Obsidian と同じ最初の一致。ブロック参照 `^id` は対象外。
- `registerMarkdownPostProcessor` で `.internal-embed` の src を解決して中身を差し替え、既存の core / layout / node-renderer で描画する。描画の Component は `MarkdownRenderChild` で埋め込みの寿命に合わせる。
- 埋め込み内では編集しない。埋め込みから元ノートをマップで開ける。埋め込み内のリンク・画像は元ノートを基準に解決する。
- 枠の高さは既定値で Fit する。大きなマップでもホストノートの表示を止めないよう、第一階層より下を折りたたんだ状態で描く。
- Mappy を無効化すると通常の見出し＋箇条書きの埋め込みに戻る。

**受入条件:** 埋め込みの描画で元ノートもホストノートも書き換えない。元ノートを別の leaf で編集すると埋め込みが更新される。`#見出し` の部分木がその区画の内容と一致する。存在しないノート・`mappy: true` のないノートは通常の埋め込みのまま。ホストノートを閉じたとき描画の Component とイベントが残らない。2,000 ノードのマップを埋め込んでもホストノートの操作が止まらない。明色・暗色テーマで破綻しない。

**実機確認（2026-09-20、LEV-64。E34）:** 専用 test-vault の Obsidian 1.14.2、Mappy 0.2.1（`artifacts/lev-64-embed-e2e/record.md`）。閲覧モード: 5 つの `![[…]]` が読み取り専用のマップ（`uneven-branches` 9 ノード、`embed-timeline` 5、`embed-hierarchy` 4、`embed-hierarchy#同じ名前` 3 ＝「回復する」の下の最初の一致の部分木、`embed-2000` ルート＋13 でバッジ 182）で、区画の `.internal-embed` を差し替える経路、枠 700×320、「マップで開く」ボタンあり。`heading-document`（`mappy: true` なし）・存在しないノート・`embed-hierarchy#^block` は Obsidian の通常の埋め込みのまま。閲覧モードは区画を遅延描画するので、見えている区画の分だけ MapEmbed が生まれ、画面外の区画は DOM から外れる。ホバープレビュー: 別ノートの `[[embed-host]]` に実ポインター（⌘）を乗せると `.popover.hover-popover` の中の埋め込みがマップ（枠 386×320、閲覧モードと同じ経路）で、外すと閉じる。明色・暗色: 枠・線・バッジが読める（埋め込みはホストのノートの配色に従い、設定 `theme` は `.mappy-embed` に付かない）。別 leaf の編集: `embed-timeline` を分割 leaf の Markdown で末尾に 1 行入力すると保存前に 71 ms で 5 → 6 ノード、保存後もそのままでホストの原文は不変、Undo → 保存で戻る。開閉・リンク・「マップで開く」: 枠の中の開閉ボタンで 9 → 10 → 9 ノード（原文不変）、ノード内リンクの ⌘クリックで新しいタブに Markdown が開きホストは残る、「マップで開く」の ⌘クリックで元ノートが map view で開きホストは残る。ホストを閉じる: リスナー（editor-change／modify／rename／delete）が起動直後の基準値に戻り、`.mappy-embed`・`.mappy-embed-host` は 0。2,000 ノードのホスト: ライブプレビューで `embed-2000` を描いた状態で末尾に 20 文字入力と全体スクロールをして rAF の間隔 p50 8 ms／p95 12 ms／最大 30 ms。保存のたびの描き直し: ホストに 1 行足して保存しても枠は同じ要素のまま（`ctx.addChild` の子は保存では unload されない）。無効化・再有効化: `disablePlugin` で閲覧モードが再描画されて 5 つとも通常の埋め込みに戻り（リスナー editor-change 0）、`enablePlugin` で開いたままの閲覧モードで 5 つが自動的にマップに戻る（開き直し不要）。全手順の後で `embed-host.md`・`embed-timeline.md` は変更なし。**ライブプレビューは不安定**（この日の時点。LEV-91 で修正し、2026-09-21 に実機で再確認済み。下記）: `embed-host` を開くと `uneven-branches`・`embed-timeline`・`embed-2000` はマップ（容器を claim する経路）になるが `embed-hierarchy` と `#同じ名前` は通常の埋め込みのまま残り、3 つの埋め込みを同時に描く一時ノートでは 1 つ目だけマップというケースも出た（2 つまでのノートと画面下の 1 つは全部マップ）。原因: Obsidian は区画を未接続で渡し、容器 `.internal-embed` が document に接続されるまで 17〜28 ms かかる描画があるが、`MapEmbeds.claimContainer` は「未接続なら次の 1 フレームだけ見直す」ので間に合わないと claim をあきらめる。ノートの形式や位置ではなくタイミングの問題で、埋め込みが多いノートほど外れやすい。未実施: モバイル、PDF 書き出し・印刷（LEV-57 の前提 4、対象外）、見出しの大文字小文字（fixture の見出しは日本語のみで、実機では区別できるケースがない）。

### M11: 左右バランス配置

ルートを中央に置き、第一階層を左右へ振り分ける 4 つ目のレイアウト。`mappy-layout: balanced` を初期表示設定にし、レイアウトボタンと frontmatter の扱いは M4・M8 と同じ規則にする。

- 第一階層は Markdown の順序で左右へ交互に振り分け、以下の階層はその側へ伸びる。振り分け規則は 1 つに固定し、左右を手動で選ばせない。
- 選択・編集・折りたたみ・ズーム・ドラッグによる並べ替え・親変更・フリートピックの合流の事前表示は通常マップと共通。左側の枝ではドラッグの判定と線の幾何を鏡像にする。位置未設定のトピック（ルートの中央に揃えた列）を合流先にしたときも、事前表示の間は合流先の親が運んだルートから離れない: 仮ノードで広がった木を列に積み直さず、位置未設定のトピックは仮ノードのない配置の位置に留め、列の積み直し（広がった木の中央揃えを含む）は離した（またはスロットが消えた）時点で行う。階層図と、本体の枝を運ぶ事前表示も同じ規則（2026-09-21 決定、LEV-95）。子を持つ位置未設定トピックの子列へ別のトピックを運ぶ場合は、事前表示が出る前から位置未設定の木をドラッグ開始時の仮ノードなし配置に留め、運んでいる木を避ける積み直しをドラッグ終了まで遅らせる。これにより右子列末尾などの `snapTarget` を失わず、preview 前後も親ルートを固定し、原文順に対応する左右列の子順へ合流する（2026-09-21、LEV-117。階層図・タイムラインも LEV-125 で同じにした）。その代わりドラッグ中は他の位置未設定のトピックが運んでいる木を避けず、避ける積み直しは離した時点で一度だけ起こる（LEV-95 で `occupied` から運んでいる木を外す案を退けた理由はこの挙動変化。子列へ合流できないことの方を重く見て受け入れた）。留める配置はノートとレイアウトが一致するものだけを使うので、ドラッグ中にレイアウトが切り替わればその時点で積み直す。階層図・タイムラインでも同じ固定をかけ、子の行の末尾へ運んだときに親が逃げないことを jsdom・headless Chrome・Obsidian 実機で確認した（LEV-125）。
- Excalidraw 挿入と埋め込み表示（M10）に反映する。

**受入条件:** 切替で内容を書き換えない。左右に分かれても兄弟の順序が Markdown と一致し、並べ替えが両方に反映される。折りたたみと再展開の前後で内容が欠落しない。2,000 ノードで操作可能で、配置時間を `scripts/measure-layout.mjs` に加えて記録する。

**実機確認（2026-09-20、LEV-61。E26／E13／E19／E30（E33）／E10）:** 専用 test-vault の Obsidian 1.14.2、merged main `c9c6746` のビルド、Excalidraw 有効。ホストは `uneven-branches.md` の複製に `## 追加トピック` を足した一時ノート、ドラッグは CDP `Input.dispatchMouseEvent` の実ポインター（`artifacts/lev-61-balanced-e2e/record.md`）。E26 左右バランス版: 左下の「左右バランス」で frontmatter に `mappy-layout: balanced`、本文は不変、第一階層は原文順に 右・左・右・左（深い一列の枝 R、多数の兄弟 L、長い日本語 R、リンクと画像 L、コード R、同じ名前 L、同じ名前 R、空に近い枝 L）、Markdown に切り替えて戻すと左右バランスのまま、「通常マップ」でキーだけ消える。E13: 左側の「多数の兄弟」の開閉ボタンはノードの左、閉じるとバッジ 24 が左に出る。並べ替え: 「兄弟 2」を「兄弟 5」の上辺へ → 事前表示（ゴースト・スロット・青線）→ 兄弟 4 の後ろ（左側のまま）、「兄弟 2」を右側の葉「コードの後の子」の中央へ → スロットが右側に出てその子になる（右側に移る）、「兄弟 2」を左列の「リンクと画像」の上辺へ → 第一階層の「長い日本語」の後ろに入り、以後の側が入れ替わる（リンクと画像 L→R、コード R→L、空に近い枝 L→R。規則が原文順の交互で固定なので仕様どおり、記録のみ）。⌘Z 3 回で 3 つのドラッグが順に戻り原文と一致。フリートピックの合流: 「追加トピック」を左側の葉「兄弟 24」の左隣へ運ぶとスロットが出て、離すと `  - 兄弟 24` の下に `    - 追加トピック`、`## 追加トピック` は消え、⌘Z で戻る。E30／E33 Excalidraw 挿入: 104 要素が 1 グループ（rectangle 9・text 47・image 2・line 46）、ルートが中央で左に 32・右に 14 ブロック、第一階層の側はマップと同じ、線 46 本すべて直角の折れ線。**ブロックの座標はマップの DOM と一致しない**: `excalidraw-bridge.ts` は「原点に作って Excalidraw 自身に測らせ、配置してから動かす」設計なので、Excalidraw の文字幅がマップの DOM と違うノード（長い日本語のタイトルは DOM では max-width 360px で折り返し、Excalidraw では 1 行 1,232px）から先が横にずれ、47 ノード中ルート基準の座標が 1.5px 以内なのは 1 つ。ブラウザ検証ページ（`balanced-scene`）は同じ測定器で測るので一致する。側・順序・直角の線は一致し、設計どおりなので harness.md E33 の期待を「側と構造が一致する（座標は Excalidraw の文字幅で決まる）」に直した。E10: `embed-2000` を view state の balanced で開くと 4.0 s で 2,000 ノード（ファイルに `mappy-layout` は書かれない）、第一階層は ノード 1 R／184 L／367 R／550 L、左側の「ノード 184」を閉じると 1,818 ノード・バッジ 182、再展開で 2,000、ホイールのパン 10 回とズーム 6 回の間の rAF 間隔 p50 4 ms／p95 5 ms／最大 30 ms、原文不変。ホスト以外は不変。未実施: `scripts/measure-layout.mjs` への 2,000 ノードの配置時間の追記（ブラウザ検証ページの計測は `artifacts/lev-58-balanced-layout/record.md`。実機の 4.0 s は読み込み・解析・描画込み）、トラックパッドの実操作感（合成ポインター）。

### M12: マップから他のマップを検索して呼び出す

マップを開いたまま Vault 内の別のマップを検索し、現在のマップ上に呼び出して並べて見る。呼び出しは Markdown 上では通常の埋め込み記法の項目であり、表示は呼び出し先の木を現在のマップの枝として継ぎ足す（枠に縮小しない。LEV-82 で LEV-69 の枠を置き換えた）。

- マップにフォーカスがある状態でコマンド（ホットキーはユーザー割り当て）から検索 UI を開き、`mappy: true` を持つノートをタイトルとパスで絞り込む。
- 選ぶと、選択ノードの子の末尾に `![[別マップ]]` を 1 行の項目として追加する。何も選択していなければ、文書末尾に `![[別マップ]]` を見出しにした最上位区画（フリートピック、M7）を追加し、位置は未設定（本体のそばの列）に置く。どちらも通常のノード追加・トピック追加と同じ差分・履歴で保存する。
- 呼び出したマップは、そのノードを呼び出し先のルートとして、呼び出し先の本体の木を現在のマップの枝と同じ見た目・同じレイアウト（通常・タイムライン・階層図・左右バランス）で描く。縮小や枠はない。呼び出した部分は読み取り専用で、選択・折りたたみ・ダブルクリックで元マップを開くことだけができ、編集・並べ替え・削除・ドラッグは効かない。呼び出し元のノード（`![[…]]` の項目）自体の編集・移動・削除は通常のノードと同じで、削除すると呼び出した木ごと消える。
- 自分自身、または呼び出しの連鎖が元に戻る埋め込みは再帰せず、リンクとして表示する。呼び出し先の中の呼び出しはリンクのまま（1 段だけ）。

**受入条件:** 呼び出しで変わるのは現在のノートの 1 項目（未選択なら 1 区画）だけで、呼び出したマップの元ノートは変わらない。Undo で項目（区画）ごと消える。同じマップを複数回呼び出しても壊れない。呼び出したマップの元ノートを編集すると現在のマップ上の表示が更新される。循環参照で描画が止まらない。2,000 ノードのマップを呼び出しても現在のマップの操作が止まらない（呼び出し先はルートの子まで開き、それより下は折りたたんだ状態で始める）。書き出し（M13）と Excalidraw 挿入（M6）に呼び出した木が通常のノードとして入る。見出しが `![[別マップ]]` だけの最上位区画は、呼び出し先のルートをトピックのルートとして、その木を枝として描く（項目の呼び出しと同じ読み取り専用の扱い）。`mappy-topics` のキーはその見出しの文（`![[別マップ]]`）で、ドラッグで位置を保存・合流・切り離しができる。

### M13: PNG／SVG 書き出し

現在のレイアウトと折りたたみを SVG に書き出し、PNG はそれをラスタ化する。Excalidraw 挿入（M6）と並ぶ、Obsidian の外へ持ち出す経路。

- HTML ノードは `foreignObject` で包み、画像は data URL として埋め込む。線は既存の SVG をそのまま使う。
- 現在のテーマ（明色・暗色）の見た目で出す。書き出し先は Obsidian の添付ファイル設定に沿い、コマンドから実行する。
