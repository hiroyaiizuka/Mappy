# 表示・入力フィードバックの反映

更新: 2026-09-16。ユーザー提供の MarkMind／XMind 画像と、Mappy 試用中のフィードバックを元にした仕様。実装した項目についても、実機での達成確認は `artifacts/` の各実行記録を参照する。モバイル、OS の日本語 IME、性能の確認を先取りして完了としない。

## Markdown と表示の対応

ルートは H2、下位のノードは箇条書きのインデントで表す。項目の最初の行がノードのテキストであり、別のタイトル欄を作らない。

```markdown
## 講座の構成
- はじめに
  - この講座で学ぶこと
  - 全体の流れ
- 絞る
  - 注意を絞る
    - シングルタスク
- 回復する
  - 睡眠
    - 夜の過ごし方
```

文書直下に H2 以外の見出しがなければリスト形式を使い、インデント変更を親子関係へ反映する。2スペース・4スペース・タブを CommonMark の実際の構文に従って扱い、見出しのような6階層制限は設けない。番号付き・タスクリストと、その中の枝はノード化せず原文を保持する。

H1・H3 など H2 以外の見出しがある文書は従来の見出し形式を維持する。見出し形式の深さは H6 まで。旧文書のリスト形式への変更は、右クリック「リスト形式に変更」またはコマンド「現在のマップをリスト形式に変更」だけで実行し、閲覧では変更しない。変換後も本文・タイトル・親子関係を保てることを検証し、構造が変わる入力は拒否する。変換はマップの Undo で元へ戻せる。

最初の見出し区画を表示ルート（本体）にし、後ろの最上位区画はフリートピックとして配置する（product-plan §5 M7）。見出しのない文書はファイル名の仮想ルートを使う。本文・リンク・画像を原文範囲で保持し、リストの本文編集では最初の子より前の継続本文を扱う。親の子リスト後の文章を、子の本文や子の移動範囲へ混ぜない。

## 見た目

| 対象 | 仕様 | 確認すること |
| --- | --- | --- |
| ルート | 濃い灰色の面と角丸の枠 | H1 だけでなく H2 開始でも正しく判定する |
| ルートの直接の子 | 背景と枠を持つステージ | 通常マップ／タイムラインで階層の区別が分かる |
| 下位ノード | 基本はテキストだけ | テキストに下線を引かず、選択枠は編集・選択状態を示す |
| 通常マップの線 | 親の右辺中央から子の左辺中央へ直角線 | ノードの下や内部へ線を伸ばさず、ルートの右側を広めに空ける |
| タイムラインの軸 | ルート・第一階層を水平に並べ、箱の外側の区間を接続 | 重複した軸線が箱や文字を横切らない |
| タイムラインの枝 | 第一階層から上・下へ交互に伸ばす直角の枝 | 子の高さ中央で曲げて左端で止め、枝どうしが重ならない |
| 折りたたみ | 隠れる子孫の総数を小さな丸いボタンに表示 | 直接の子だけでなく孫以下も数える。再展開で内容が戻る |
| 展開中の開閉操作 | 枝の分岐点へホバー／フォーカスすると丸い − を表示 | ノード全体へのホバーで出さず、常時の記号が余計な線に見えない |

折りたたみはビュー内の表示状態だけを変える。レイアウトの明示選択は次回の初期表示として frontmatter に保存するが、本文は書き換えない。長いテキストや画像のサイズは DOM を計測して配置へ反映する。上下の枝は、同じ側の枝に必要な幅を確保し、反対側の空間を共有する。バッジは文字の桁数に合わせて幅を取り、操作領域も枝の間隔と全体表示の範囲に含める。

右向きの枝は親から短い共通の幹を伸ばし、その先の分岐点に開閉操作を置く。タイムラインの第一階層は上または下の縦幹上に置き、閉じた場合はステージの上側に件数を出す。3・4桁の件数がノードや次の枝に重ならないことも検証対象にする。

## 新規作成・インライン入力

- ノード選択中の Enter で兄弟、Tab で子を追加する。リスト形式では下位を空の箇条書き、ルートを H2 として追加し、その場で編集に入る。従来の見出し形式では ATX 見出しとして追加する。
- 新規追加時の「ノードを編集」モーダルと「入力…」のプレースホルダーは表示しない。
- 入力欄は空のとき狭く、1 行のまま文字に合わせて横へ広がり、ノードの文字の 20em（全角約 20 文字）を超えると折り返す。確定後のノードも同じ幅で折り返し、入力中と確定後で行が変わらない（LEV-198）。
- 既存テキストは F2 またはダブルクリックで編集する。本文の長い文章は右クリックから任意で開く本文編集画面に残す。
- テキスト編集中の Enter は確定、Tab は確定して子を追加、Escape は入力を取り消す。追加済みの空ノードそのものを取り消すときは Undo を使う。
- 変換中の Enter／Tab は確定・構造変更に使わない。保存に失敗したらドラフトとエラーを残し、古い原文で上書きしない。

## 内部リンクの候補

ノードの textarea で `[[` と入力したとき、Vault のノート・パス・別名と添付ファイルを候補に出す。PNG・SVG・PDF も対象にし、`![[` から選んだときは埋め込みの `!` を保持する。これは専用の候補 UI で、Obsidian 標準エディタそのものの埋め込みではない。標準 Markdown ビュー側は Obsidian の補完を引き続き利用する。

受入条件:

- 日本語や空白を含むノート名、同名ノートのパス、frontmatter の別名から選択できる。
- 画像・PDF などの添付ファイルを選んだときも、拡張子とリンク先を保持する。
- 選択すると入力中のリンク範囲だけを置き換え、前後のテキストと入力済みの別名を保持する。
- 候補表示中の Enter／Tab は候補選択だけを行い、同じ操作でノードの保存・追加をしない。
- マウスで候補を選んでも、先に textarea の blur 保存が走らない。
- 候補を閉じる操作と編集全体を取り消す操作を区別し、編集終了時は候補を解放する。

見出し・ブロック参照候補など、標準補完の全機能は今回の実装範囲に含めない。リンクの描画・クリック時は元の Markdown ファイルを基準に解決する。

## 操作 UI

キャンバスを表示領域全面に広げ、上部・下部に操作のためだけの帯を割かない。マップ／タイムライン／階層図／左右バランスの切り替えは左下、操作メニュー（歯車 1 つ）は右上、ズーム操作は右下に浮かせて置く。子追加・兄弟追加・本文・画像・Undo/Redo などを並べる操作行は置かず、キーボードとノードの右クリックメニューから使えるようにする。右上の歯車は Markdown に切り替え・マップを検索して呼び出す・書き出す の 3 項目だけのポップオーバーで、ノードの操作はキーと右クリック、そのほかはコマンドパレットに置く（LEV-77 の全項目メニューは項目が多く、Obsidian の `Menu` が右端で画面外に出たため LEV-81 で置き換えた）。

## 確認の分担

純粋ロジックでは原文の保全、見出しの階層、幾何配置、接続線の終点、子孫数、補完の置換範囲を検証する。DOM テストでは入力、候補選択、イベント伝播、破棄時の処理を検証する。

実機では参照画像との見た目の一致、標準 Markdown との往復、リンク遷移、ズーム、保存後の原文を確認する。試用中の `test-vault/` を初期化せず、配布物だけを更新する。手順とケース一覧は [harness.md](./harness.md) を参照する。
